# 穿线 WIRE 器件验收报告

日期：2026-11-11。功能：多输入、多输出穿线器件，内部对应关系由 elab 证明，时钟树和复位树共用。用户仅填写 module、直接父层及关注端口，不手工指定内部配对。

## 1. 实现及数据语义

- 配置增加 `kind: wire`，使用 `clock_outputs` / `reset_outputs` 多输出字段。旧单输出规则不变。
- 输出在本实例内部通过 Language Model 反查到关注输入；逐输出提交端口断点。普通外部边保留原 ID 和证据，内部关系单独保存 `internal_connections`。
- 完整证据必须证明唯一关注输入，才标记 `verified` 并绘制内部线。常量、反相、条件/逻辑运算、未配置输入、时序电路及未知表达式不推断为直连。
- 逐端口网络归属、上下游遍历和环路检查区分独立通道。实例只有一个真实 ID，多个通道不重复增加实例计数。
- Tk 与 SVG 使用相同器件图形；每个输出有独立锚点。属性列出内部对应关系，端口旁保留实际例化连接名；总线整体表达式仍标注“整口”。
- 后台布局接收多输出元数据。沿连线导航保留当前通道，独立分支窗口裁去无关通道；SV 分支分析使用相同的已证明通路。
- 新增 SQL 端口队列有界读取节点数据，缓存上限 2,048 个节点；旧的无穿线大图继续使用原有批量 SQL 遍历。

## 2. 验证环境

共享工作区 `/mnt/hgfs/VMshare/clocktree7`，Linux VM、Python 3.6.8、Tk/Tcl 8.5.13、Verdi O-2018.09-SP2、VCS O-2018.09-1。图形测试使用隔离 Xvfb，未覆盖用户日常会话。目标模式测试安装禁止 Netlist Model / output load 调用的运行时探针，确认内部追踪没有改回全负载遍历。

Windows 主机使用现有 Python/Tcl 运行自动测试。一次以上批量启动曾出现 Anaconda `init.tcl` 读取错误；单独复核正常，显式指定本机已有 `TCL_LIBRARY` 后完整测试通过。该环境变量只用于本次主机验收，未写进产品或目标 EDA 环境。

## 3. 逐项结果

| 项目 | 数据和核对方式 | 结果 |
| --- | --- | --- |
| 交叉接线 | `a → y`、`b → x`，不按端口顺序配对 | 通过 |
| 别名、一入多出、缓冲 | `a → alias_a → y`，以及 `buf(z, alias_a)` | 通过，保留两条通道 |
| 逐位重排 | `q[5:2] = {bus[1:0], bus[3:2]}` | 四位全部符合独立 oracle |
| 模式覆盖 | clock/reset × target/full，10 个实例、9 条外部边、7 组内部关系 | 四种组合通过，6 个独立网络 |
| 非直连逻辑 | 把输出改为 `a & b` 和 `~a` | 两个输出明确未解析，其余 5 组关系保留 |
| 缺失输出 | 配置不存在的 output | 端口校验问题可见，未生成虚假连接 |
| 内部追踪超时 | watchdog 阈值 1 秒，独立测试 hook 阻塞 5 秒并写未提交后缀 | 超时终止并恢复；后缀撤回，1 个已提交通道保留，5 个剩余输出跳过，后续实例继续 |
| 内部断点轮换 | 完成 `x`、`y` 后分别请求轮换 | Verdi 重启 2 次，最终 7 组关系与基线一致 |
| 分支隔离 | 内存图/SQLite 索引的上下游、高亮、独立窗口 | `g0 ← w.x ← w.b ← s1` 不包含 `s0` 和另一通道 |
| 伪环路与真歧义 | 同一真实穿线实例经过不同通道被分支二次访问；一个输出有两个输入候选 | 前者不误报信号环路，后者不标 verified |
| 原生 GUI 与恢复 | 规则编辑、导航后退、内部关系、独立分支、SVG、两次进程启动 | Tk 8.5.13 通过，回调异常 0 |
| SV 分支与 bit | 从真实 elab 读取 7 个末端和起始信号，逐项断言后导出 | 7 段生成、0 跳过；交叉和重排后的 `$var_pll0` 全部正确 |
| 自动测试 | 全部现有用例及新增配置、图、SQL、布局进程、SV 测试 | **314 passed，1 skipped**；跳过项为 Windows 不适用的 Linux 包装脚本测试 |

真实 bit oracle：`g3` 末端为 `q[2]`，起始为 `bus[2]`；`g4` 为 `q[3] ← bus[3]`；`g5` 为 `q[4] ← bus[0]`；`g6` 为 `q[5] ← bus[1]`。`g0` 起始为 `b`，`g1`、`g2` 起始为 `a`。

## 4. 压力与回归

**1,000 个真实 elaborated 穿线实例**，每实例 2 输入、2 输出，共 **4,000 次端口追踪、2,000 组内部关系**。全量逐实例核对交叉映射通过，2 个独立网络，未解析和诊断均为 0。提取耗时 **70.733 秒**，监控记录的 Verdi 与提取控制进程峰值合计 RSS **0.245 GiB**。这是合成 RTL 在本 VM 的实测，不代表超大商业芯片的总 elab 加载内存。

复跑设备 doctor、子系统 target/full、子系统异常及超时、原 SV 原生提取与 VCS 编译、SV 两次 GUI 启动，共 7 个回归任务通过。已有开源 KDB 的目标实例与外部边集合保持一致：

| 开源设计验收范围 | 实例 | 外部边 | 结果 |
| --- | ---: | ---: | --- |
| OpenTitan 已记录 clkmgr 范围 | 15 | 10 | 与历史完整核验一致 |
| PULP 已记录 SoC 目标范围 | 62 | 48 | 与历史完整核验一致 |
| OpenC910 已选直接父层子网 | 30 | 29 | 与历史完整核验一致 |

开源 KDB 回归确认旧器件行为未回退；新增穿线功能的正反例由上述专用 RTL 证明，不把未配置穿线的开源项目冒称为穿线全覆盖测试。

## 5. 便携与证据

候选便携包 `clocktree7-wire-20261111-rc1` 解压到 `/home/host/clocktree7-portable-qa/clocktree7-wire-20261111-rc1`，清除 `PYTHONPATH` 并设置 `PYTHONNOUSERSITE=1`，从该目录重新生成独立 RTL 与工作目录。**MANIFEST 中 275 个项目文件逐项校验通过**（包内共 276 个文件，另一个是清单本身）；8 项原生矩阵（含超时、两次断点轮换）、真实 bit 的 7 分支 SV 导出，以及 Tk 两次独立启动恢复全部通过。没有使用共享目录的 Python 源码，也没有把 EDA 安装或许可打入包中。

发布代码仍使用目标设备已有 Python/Tk、Verdi 和许可。源码、使用手册与验收脚本一同交付；测试日志、商业/第三方 KDB、用户历史及本机凭证均不包含在包内。

- `gui-release/`：两次独立启动、规则截图、器件截图、独立窗口与 SVG。

可复跑命令：`python3 scripts/check_wire_device.py --phase matrix --out <新目录>`；压力模式为 `--phase stress --count 1000`；GUI 模式为 `gui-write` / `gui-read`，首次附 `--result <clocktree.json>`；SV 模式为 `--phase sv --result <clocktree.json>`。

本次未使用用户商业芯片数据；不宣称所有 NPI 版本、任意复杂表达式或多维 packed 接口均已证明。未知表达式继续进入问题表，旧结果不凭新增配置补造内部线。
