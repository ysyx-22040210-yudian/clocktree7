# RTL 时钟树重建工具计划（有序七层、全量时钟网络修订稿）

需求与设计记录。当前提取器、Tk 图形界面及虚拟机验证已实现，实际使用方法见 [GUI 操作手册](GUI_USER_MANUAL.zh-CN.md)，结果见 [验证摘要](VALIDATION.zh-CN.md)。本文保留原技术选型讨论；交付版使用 Tk/ttk、原生 Canvas、共享 SVG 几何和基本 NPI，以适配 CentOS 7 与现有许可证。

## 用户已确认的目标与连接规则

用户只配置 7 个有序 RTL 层次、每层的 module 定义名，以及每个 module 关注的时钟输入口和唯一输出口。具体实例、源信号、实例之间的前后连接及所有扇出，均由工具解析 elab 库后自动确定。用户不提供实例连接表，不需要手工指定哪个模块连接哪个模块，也不要求额外填写 MUX、ICG、OCC 等类别才能提取。

恢复范围为七层配置覆盖的全部目标实例及其全部关注端口之间的完整时钟网络。必须包含全部初始时钟源、所有扇出、所有汇合、同层连接、跳层连接及位于任意层的全部分支末端；多个独立时钟源产生的多个时钟树一并恢复。示意图中的局部分支和开发初期的片段验证都不代表最终交付范围。

完整结果采用全局实例/端口有向图表达：互不相连的时钟树表现为多个连通分量；不同来源通过 MUX 等目标结构汇合时，保留真实共享节点及全部输入连接，不人为拆成互不相关的树。同一实际实例只建立一个节点，节点可由多个初始时钟源到达。解析失败、孤立或不符合七层规则的目标实例也纳入结果与诊断，不因无法挂到某一棵树上而省略。

7 个层次按 L1 至 L7 固定排序，层次编号用于约束时钟传播及界面分栏；每层同时保留用户给出的 RTL 层次标识/范围。层次编号与 elab 中的真实实例路径分别存储，不按路径深度推算所属层次。每条分支的实际末端可以位于 L1 至 L7 中任意一层，末端层号由连通提取确定。此前将 7 个层次仅作为无顺序 scope 分组的假设、以及要求全部分支必须到达 L7 的假设均已撤销。

| 规则 | 已确认行为 |
| --- | --- |
| 起点 | 初始时钟从 L1 内模块的关注输入口进入 |
| 终点 | 每条分支可以在 L1-L7 任意层结束，末端层号由实际连接决定；L7 为配置中的最高层号 |
| 同层连接 | 允许一层内多个实例串接、分支或汇合 |
| 跨层连接 | 允许从较小层号连接到任意较大层号，例如 L2 直达 L5 |
| 扇出 | 一个关注输出可以连接多个下游实例的关注输入 |
| 全量恢复 | 枚举七层全部匹配实例，遍历全部关注端口及全部分支；不要求用户选择单一根或终点 |
| 多源与共享节点 | 全部时钟源及独立时钟树统一保存；MUX 汇合或共享下游保留实际连接 |
| 缺失中间层 | 合法；不补造 L3/L4 等缺失节点，也不要求每条分支经过全部七层 |
| 缺失后续层 | 合法；在 L2、L3、L5 等层结束的分支同样属于全量结果 |
| 逆序连接 | 不符合约定；保留数据库证据并显示异常，不静默删除或改向 |

对一条实例间连线，层次约束为 `target.layer >= source.layer`。等号表示同层连接，大于表示正常跨层或跳层。同层真实环路仍应检测并报告，不能因层号相同就判为合法时钟路径。

L1 内也可能有多个模块串接，因此不是每个 L1 模块输入都属于外部根。任一层都可能有多个模块串接，因此不能仅凭到达某一层就停止；需要恢复该层内部以及后续层的全部实际目标连接。对每个分支，穷尽可解析下游后若不再到达关注目标端口，则标记其在当前关注结构网络中的末端或范围边界，并记录最后一个目标实例输出口及停止依据。这个末端不等于已证明的物理时钟树叶端。

分支在 L1-L6 结束本身属于正常情形，不标记为“未到达 L7”或“不完整”。由于黑盒、未知逻辑、深度限制或超时而尚不能确定下游的分支，标记为未解析断点。真实悬空另外记录其电气状态。一个输出的不同扇出可以分别到达目标模块、范围末端或未解析断点，状态逐分支保留。L1 之外的无来源输入仍按入口规则单独报告。

选择器允许 N 个关注输入和 1 个关注输出；门控、OCC 等其他结构允许 1 个关注输入和 1 个关注输出。一个输出允许连接多个下游实例。同一个 module 的多个实例必须分别显示。暂按每个关注接口为一个时钟位处理；总线须显式选择位或采用逐位规则，不能默认将整条总线视为单一时钟。

提取结果表示所有可能的结构传播路径。当前未提供 MUX 选择、门控使能和测试模式的条件规则，因此首版同时显示 MUX 的全部候选时钟输入；当前模式的有效路径属于后续可选能力。

## 输入与数据约定

界面提供 L1 至 L7 共 7 个有序条目。用户必填信息只有：

- RTL 层次标识/范围，例如完整 scope 路径；条目顺序自动产生层次编号。
- 该层中的 module 定义名列表。
- 每个 module 的关注输入口列表和唯一关注输出口；支持显式位选。

按这些信息在 elab 中自动枚举匹配实例，提取每个实际实例的完整路径与所属层次。模块有一个关注输入还是多个关注输入由列表自然表达；显示类别可以后续附加，但不构成必填项。设计库导入属于工程加载信息。

配置可以导入、导出和保存为 JSON。下面仅展示前两层的格式，其余层按同样方式配置，端口和 scope 均为示例：

```json
{
  "layers": [
    {
      "index": 1,
      "hierarchy": "soc.u_clk_src",
      "modules": [
        {
          "module": "clk_mux2",
          "clock_inputs": ["clk0", "clk1"],
          "clock_output": "clk_o"
        }
      ]
    },
    {
      "index": 2,
      "hierarchy": "soc.u_crg",
      "modules": [
        {
          "module": "clk_gate",
          "clock_inputs": ["clk_i"],
          "clock_output": "clk_o"
        }
      ]
    }
  ]
}
```

加载后先校验层次范围、module、端口方向、位宽和实例匹配数量。同一实例在同层重复命中时去重；被不同层同时命中时报告归属冲突，不通过复制节点或猜测连线顺序掩盖冲突。相同 module 类型可以出现在不同层，但必须能通过用户给定的 RTL 层次范围区分实际实例。

## 实现架构

1. **Verdi/NPI 提取器**：在可运行用户 Verdi 的机器上加载原设计，枚举全部目标实例，对全部关注输出及输入组织批量追踪，导出全量原始网络、实例清单及诊断信息。
2. **Python 图处理层**：校验配置，编排提取任务，将原始端口网络转换为稳定的工具数据格式，形成包含全部时钟源和连通分量的全局图，并检查七层顺序、根与终点的可达性及实例/端口覆盖情况。
3. **React + TypeScript 图形界面**：使用 React Flow 表达独立端口，使用 ELK 布局；按 L1 至 L7 固定分栏，并处理同层串接、扇出、汇合和跨层跳接。

设计库由具备 Verdi 环境的后端加载。界面可在同机浏览器或通过内网访问；也支持导入已提取的 JSON 在 Windows 或 Linux 上离线查看。直接导入库的具体入口在运行环境对齐后确定。

- https://reactflow.dev/learn/layouting/sub-flows

## 连通关系恢复

1. 加载足以覆盖七层及跨层连线的设计上下文。按每层给定的 RTL 层次范围和 module 名枚举全部实例，为每个实例确定完整路径与层号。在开始追踪前先把全部目标实例加入全局图，保证未被根搜索到的实例仍被覆盖。
2. 建立每个实例的关注输入口/输出口索引。模块内部“关注输入到唯一输出”按用户提供的结构抽象记录；实例之间的连接必须来自数据库。
3. 从全部目标输出沿实际网络向下游追踪，获取所有最近目标输入口，建立 `source_instance.output -> target_instance.input` 的边。一个输出存在多个分支时全部保留；到达目标输入后结束该段，再从目标实例自己的输出继续。
4. 穿越普通层次端口、纯连接 assign、位选和拼接，保留方向及位映射；BUF、INV 等按明确规则穿越，记录反相等属性。经过的真实层次路径可以与 L1-L7 编号不同，不影响传播分层。
5. 连通提取不以“下一层”作为搜索边界，也不通过层号提前过滤数据库连线。实际发现 L2 到 L2、L2 到 L3、L2 到 L5 时均先记录；之后分别判为同层、相邻跨层或跳层。
6. 对实际边检查 `target.layer >= source.layer`。逆序边和自环/环路保留为异常证据，不反向改线，也不删除后伪装成正常时钟树。目标实例之间若存在中间目标模块，保留逐段连线，不能额外建立跨过它的快捷边。
7. 从关注输入向上补充来源，识别真正进入 L1 的根。MUX 各输入口分别追踪，保留不同来源；L2-L7 中不能追溯到 L1 的支路单独报告。
8. 对任意层继续恢复同层和跨层连接，直到该分支的目标结构链末端或未解析断点。末端可能处于 L1-L7 任意层，不施加到达 L7 的条件，也不将较早结束的分支当成异常。不继续把未配置的寄存器 clock pin 展开为首版必需端点。计算从全部 L1 根到各节点及任意层末端的结构可达性，作为来源/分量信息；黑盒、超时等造成的断点单独分类。
9. 遇到未配置组合逻辑、分频时序逻辑、黑盒或无法解析对象时，显示具体停止点与原因。OCC 等已配置模块作为结构节点，不依赖穿过其内部寄存器才能连接。独立目标实例及所有异常分量同样保留在图中。

所有目标输出都进入处理队列，所有关注输入都做反向来源检查。处理持续到队列清空、全部可解析分支已穷尽；不会在找到第一条根到末端路径、首个下游、单个根或单个末端后结束。对共享节点/网络去重时仍要记录新的入边和出边，缓存命中复用完整后继边集合，防止全局 visited 集合丢失其他时钟源或支路。端口位范围和传播方向属于追踪状态。

从全局图计算全部根、位于任意层的全部已确认末端、各个连通分量，以及按需查询的根到节点来源关系。为每个末端保存所属层号、最后目标实例输出、边界或终止依据，并将未解析断点单列。完整图以节点和边保存，分支路径可按需查询；无需把大量共享路径重复复制成多棵树。

采用“先恢复实际连通，再检查七层规则”的方式。七层顺序决定有效结构和排版约束，不提供任何凭空补连线的依据。连通检查表示静态结构上的可能路径；尚未按 MUX 选择和运行模式证明各输入路径能同时激活。

NPI 的部分连接接口默认可将 assign 当成无方向连接。实现时必须检查当前调用方式，逐类验证 assign 方向与位映射。模块映射只用于已确认的时钟接口，不将 EN、SEL、RESET 等控制信号当成时钟数据口。

## 图数据与界面

节点使用完整实例路径作为稳定身份，保存原 module 定义、库、所属 L1-L7 层号、RTL scope 和源码位置。端口保留方向与位号。每条边包含源实例端口、目标实例端口、经过的 net/层次端口、允许穿越的逻辑及解析状态；跨层跨度可由两端层号计算，跳过的层不创建虚构模块节点。

NPI handle 仅在提取进程中使用，不作为跨进程 JSON ID。导出结果记录设计来源、工具版本、配置与加载选项，避免不同 elaboration 的结果混用。

界面布局：左侧为七层及 module/端口配置，中间固定按 L1 至 L7 从左到右分栏，右侧显示实例及连线详情，底部显示提取日志和异常。每栏内部另作布局，保证同层串接顺序清楚；跳层边直接跨过中间栏，不加入占位模块。

默认提供全部时钟树的全局总览：七列中的每一列可以包含任意多个实际实例，同时展示多个入口、所有分支和全部末端。提供时钟源/连通分量列表、总览缩略图、实例和端点统计，再支持选择某个时钟源或分支进行聚焦。聚焦、折叠和局部展开只影响显示，已提取数据和全量导出不随视图筛选丢失。

基本交互包括缩放、平移、搜索、层次折叠、选中节点后的上游/下游高亮、点击连线查看真实路径，以及 JSON/图片导出。突出显示全部 L1 入口及位于任意层的全部分支末端，末端保留在其真实层列内。图模型支持多源、MUX 汇合、多个连通分量；逆序和环路使用异常样式，未解析断点使用独立状态，布局时不丢边。分支没有延伸到 L7 不产生异常，也不补造尾部节点或连线。

异常至少区分：悬空、常量、多驱动、未识别中间逻辑、黑盒、层次边界、端口缺失、Netlist 对象缺失、达到深度限制、超时。达到限制不能被报告成“不连通”。

大图采用局部展开、层次折叠和结果缓存；先测量目标规模，再约定具体性能指标。按端口批量追踪并缓存子路径，避免对所有实例两两试连。

## 全量完整性验收

- 实例覆盖：逐层、逐 module 对比 elab 枚举清单和结果图，全部匹配实例必须在图中出现，未解析实例同样计入。
- 输入覆盖：每个关注输入都要列出全部可解析上游，或边界输入、常量、悬空及未解析原因；不能只保留第一个 MUX 输入来源。
- 输出覆盖：每个关注输出都要列出全部下游目标输入及停止点；不能只保留第一条扇出。
- 连线交叉复核：对全部输出的正向追踪与全部输入的反向追踪核对，发现缺边或不一致时给出具体端口和网络依据。
- 全网覆盖：全部初始时钟源、独立连通分量、共享节点及任意层末端均进入统一结果；分支结束层号不作为结果筛选条件，异常分量也保留。
- 末端判断：同时覆盖 L1-L7 各层的正常末端与“已知下游加未解析扇出”情况。只能依据已穷尽的数据库连通分析确认关注结构末端；黑盒、超时等不能当成正常结束。较早结束的正常分支不标为未到达 L7 的异常。
- 完成状态：区分任务运行结束与连接全部解析完成。深度限制、超时、黑盒及其他未解析端口仍然存在时，标为有未解析项，不能宣称全部连接已恢复。
- 图正确性：测试设计用全体期望实例和端口边集合核对；真实设计结合全量枚举与双向追踪核查，再对照 Verdi 检查代表路径。单条分支通过不能代替全网验收。

| 3. 可操作界面 | 全部时钟树七列总览、时钟源/分量导航、配置、路径详情和导出 | 用户只填层次、module 和关注端口，就能查看全部目标时钟网络，再聚焦任一时钟源或分支；全量导出包含所有分量和节点 |
| 4. 实库复核与规模验证 | 真实设计全量清单、连线核对、性能记录、使用说明 | 完成实例和端口覆盖、双向连线核查，对照 Verdi 检查代表结构；不以单分支通过代替全网验收 |

验证用 RTL 应覆盖：多个独立初始时钟源和时钟树、单源大量扇出、不同来源经 MUX 汇合及共享下游、共享节点被多次访问后仍保留所有入边/出边、分别结束在 L1-L7 的分支及所有末端、一个输出同时连接后续目标和范围边界/未知扇出、同名 module 多实例、generate/参数化、嵌套 scope、跨公共父层连接、同名不同网、异名同网、MUX 多输入、assign、位选/拼接、同层多模块串接、L2 到 L5 跳层、L1 直接到 L7、L7 内部串接、非 L1 外部根、同一实例层归属冲突、逆序边、孤立实例、常量、悬空、黑盒、未知逻辑、多驱动、同层环路及追踪限制。所有期望连接都由测试 RTL 的实际连接定义，输入配置不包含实例间连线。
