# 2026-11-10 新增功能全方位压测与修复验收

本轮重新执行真实 Verdi/VCS、原生 Tk、恢复故障和规模测试。初始基线为 `507990b13d0f5bb5d73abefb35255ec832b82040`，测试在共享目录和 Linux VM 内进行，首次失败记录保留。覆盖今天新增的辅助寄存器位追踪、分支 SV 模板、起始层复位绑定、子系统实时选择计数、独立分支画布和多输入精确导航，并复验既有提取与恢复能力。

## 结论与实际修复

在已执行的功能、压力和异常样例内，预期节点、连线、寄存器 bit、分支变量和生成代码均已按完整集合核对。压测发现并修复 **1 个共享目录运行中断问题**：Windows 读取 `status.json` 时，HGFS 可能拒绝 Linux 的原子替换，原寄存器追踪会因 `PermissionError` 中断。

修复后：

- 每条阶段事件仍写入并刷新 `events.jsonl`，端口结果仍按 SQLite 事务提交。
- `status.json` 是用于显示的快照。短暂占用只记录一次提示，不终止 NPI 追踪；高频 query/trace 快照更新合并至最多每 250 ms 一次，重要阶段立即尝试刷新。
- 实时界面和历史恢复优先读取最后一条完整事件；快照缺失、过期或末尾存在不完整日志行时仍能识别真实阶段。
- 结果、断点和事件日志的写入错误继续报错，未将磁盘故障统一忽略。

真实复现验证：在 Windows 使用禁止删除共享的文件句柄持续锁住 VM 的状态文件 **138.25 秒**。该文件始终停留在 `import`，18 个辅助端口、546 个 bit 的追踪仍全部正确完成；随后在 Tk 重开任务，正确显示“寄存器追踪完成”，继续按钮禁用，546 条结果可分页查看，0 回调错误。

另修复了验收环境问题：原截图脚本依赖用户目录里的 Pillow，隔离用户包后无法截图。现改用标准库解析真实 XWD 并写出无损 PNG；增加大小端、行填充、裁切和 CRC 检查。生产 GUI 没有新增第三方依赖。

## 复跑方法与适用边界

```bash

  --out validation/full-regression-new \
  --fanout 25000 --terminals 20000
```

只有源码便携包、没有本项目历史 KDB 时，执行自建样例和原生 GUI 回归：

```bash
source scripts/eda_env.sh
python3 scripts/check_daily_regression.py \
  --out validation/portable-check --portable-smoke \
  --fanout 1000 --terminals 1000
```

QA 截图需要 Xvfb/xwd。GUI 和提取程序继续兼容 Python 3.6、Tk 8.5 与 Verdi 2018，没有增加网络依赖或总执行超时。

本轮未取得用户目标商业芯片的实际 elab，因此不能将样例通过等同于该芯片全量签核。10 万节点画布和2万末端扩展属于合成规模测试；25,000 负载和546位专项由真实 RTL/KDB/NPI 处理。真实内存压力使用0.375/0.5/0.625 GiB阈值，未在16 GiB VM上实占64 GiB；寄存器恢复中的 RSS 阈值和查询延迟注入另行标注，不混作实际分配。

升级后的实现指纹会拒绝不兼容的旧未完成寄存器断点；旧目录和已完成结果保留可读。本轮“闪退/续跑”的结果针对同一实现版本，升级后应新建寄存器追踪任务。
