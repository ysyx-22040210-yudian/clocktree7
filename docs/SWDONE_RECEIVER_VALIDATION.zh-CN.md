# sw_done 多负载寄存器取值验收

2026-11-20 · CentOS 7.9 VM · Python 3.6.8 · 原生 Tk 8.5 · Verdi O-2018.09-SP2 · VCS O-2018.09-1

## 千负载 RTL

测试电路包含 15 个 DIV 实例。VCS 编译 RTL 并建立 KDB，ClockTree7 提取时钟树、逐位追踪辅助口并导出 SV。三个 DIV 各额外连接 1,000 个独立组合监测负载，脚本逐个比对实际负载全路径。同时验证了一个输出接 1,000 个真实寄存器位的情况。[可复跑的测试脚本](../scripts/check_swdone_concat.py)

| 电路 | 预期与实测 |
| --- | --- |
| 1,000 个组合监测负载，零接收寄存器 | 引用 `$var_swdone` 的分支报告缺少寄存器映射，候选列表为空。 |
| 1,000 个组合监测负载，一个接收位 | 自动生成。模板使用 `concat_top.b_one_capture[0]`，预览保留接收位 `concat_top.q_one_capture_0[10]`。 |
| 1,000 个组合监测负载，两个接收位 | Tk 提供两个选项，分别为两个不同寄存器的第 10 位。选定后，该分支生成一段代码。 |
| 两个 D 端信号分别直通和反相，都写入同一位 | 直接生成 `concat_top.shared_reg[5]`。分支预览与映射报告均列出 `d_direct` 和 `d_inverted`。 |
| 两个直通别名均写同一位 | 自动使用可证明等价的 `x_alias`，接收位为 `AA`。 |
| 4 位动态下标或函数旁路与已证明的时序拼接并存 | 正确生成 4 位数据输入。未解析旁路的 8 条记录保留在原始结果。 |
| 同一 D 信号扇出到 1,000 个寄存器位 | 保留所有已证实的候选，等待对这个分支的选择。 |

原始结果共 4,054 条，包含 1,046 条时序数据输入与接收位映射，以及 3,008 条未解析记录。首次导出 10 段。只为“两接收位”分支选择一次后，重新生成 11 段。其余四个分支分别为零寄存器、两组完整向量尚未选择、1,000 个接收位尚未选择，以及重复拼接未形成唯一完整向量。

通过原生 Tk 的“分析全部分支”“选择寄存器映射”和“生成 SV 代码”走完操作。界面生成的文件与相同选择下的命令行结果逐字节相同。将其与测试 RTL 一起送入 VCS，KDB 编译及展开通过。

## 时序 case 与逐位回归

`case` 测试使用 128 路扇出，核对了 160 组输入信号与接收位，以及对应的时序语句证据。9 个分支生成，4 个预设异常分支跳过。输出通过 VCS 编译及展开。两套 RTL 在同一目录执行寄存器追踪断点续跑时均复用了已提交结果。[时序 case 测试脚本](../scripts/check_swdone_case.py)

自动测试另覆盖单个命名 D 信号和旧的无名接收证据并存、同一向量中仅一位需取接收位、缺少一个 bit、未提交的追踪、无效历史选择、不同角色的确认规则，以及使用原寄存器结果读取旧版分支计划。[模板回归测试](../tests/test_sv_templates.py)

## 在其他 EDA 设备上复跑

在工具根目录执行以下命令。两个输出目录各使用一个新目录。需要使用本机真实桌面时，可在该桌面的终端调用相同的 Python 脚本。

```sh
xvfb-run -a -s '-screen 0 1920x1080x24' python3 scripts/check_swdone_concat.py --out /tmp/ct7-swdone-mixed --fanout 1000 --gui
xvfb-run -a -s '-screen 0 1920x1080x24' python3 scripts/check_swdone_case.py --out /tmp/ct7-swdone-case --fanout 128 --gui
```

在输出目录中查看 `acceptance.json`、`generated.sv` 和 `generated.sv.mapping.json`。千负载测试还输出由原生界面生成的 `generated-from-gui.sv`。
