# ClockTree7 桌面界面验收

2026-11-19，在同一台 Linux VM 上对比上一版工作台和本版。VM 使用 Python 3.6.8、Tk 8.5.13、X11/Xvfb 和 Verdi O-2018.09-SP2。所有界面截图均来自实际运行的 Tk 窗口。[操作手册](GUI_USER_MANUAL.zh-CN.md#workspace)

## 画布与高扇出公共干线

使用同一份 8,195 实例结果、1840 × 1000 的原生画布和同一组操作。记录 79 次拖动更新与 82 次缩放更新，P95 为一次更新耗时的第 95 百分位。加载包含构建视图及初次布局。RSS 为测试末的 GUI 进程常驻内存。

| 指标 | 上一版 | 本版 |
| --- | ---: | ---: |
| 拖动更新 P95 | 36.87 ms | 9.75 ms |
| 缩放更新 P95 | 26.17 ms | 7.15 ms |
| 停止缩放至细节恢复 | 147.62 ms | 134.36 ms |
| 相同局部视口内的 Tk 图元 | 8,332 | 161 |
| 首次加载 | 2.61 s | 3.51 s |
| GUI RSS | 128.5 MiB | 131.0 MiB |

干线按分叉点分段。测试从实际画布坐标点选一段公共干线，用原始布线坐标独立计算通过该处的边，双方均为 **4,096 条**，逐一比对边 ID 全部一致。水平和竖直干线的正向、反向绘制均覆盖，验证了高亮终止于正确分叉点。独立的 SQLite 回归验证了 1,400 条连接的分页，以及聚合边与普通边重合时的去重。

另一份 **100,000 节点**的合成索引图覆盖概览、局部展开、搜索、分支高亮、布局取消及过期结果处理。高亮包含 99,999 条边。连续六次采样均为 38 个概览图元、55,276 KiB GUI RSS，无 Tk 回调错误。数据分别对应高扇出局部视图和合成图概览。

## 界面与结果

| 窗口 | 上一版画布 | 本版画布 | 可见面板 |
| --- | ---: | ---: | --- |

- **交互**　检查空状态、全图、选中态、多上游定位及返回、F11 专注与恢复、模块规则和正则端口勾选、双击分支、寄存器追踪窗口、SV 模板窗口、问题表、JSON 与 SVG 导出，以及切换复位模式。Windows 与 Linux 还分别验证了三个 DPI 档位下的主题元素、输入框、按钮图标与画布底纹。
- **实时提取**　从 GUI 启动 Verdi 读取 `sv_top` KDB，8 个真实实例和 7 条连接与预期逐端口一致。选中 `sv_top.d` 后检查 `ratio_i` 绑定 `D[9:6]`、`done_o` 绑定 `done0`。缩小再放大后，所选实例和实际信号均正确恢复。
- **历史设计**　在新版 GUI 中重新打开 OpenC910（6,984 个实例、6,983 条连接）、PULP SoC（62 个实例、48 条连接）及 OpenTitan clkmgr（15 个实例、10 条连接）的既有提取结果，逐个定位真实实例并核对检查器完整路径。
- **模板与回归**　在原生 Tk 中编辑、导入模板并生成 SV，第二次独立启动恢复模板、分支计划与 SV 文件。Linux 自动测试 466 项通过，Windows 465 项通过，1 项 Linux 专用测试按平台跳过。

## 复现

在解压后的工具目录中运行。将下例中的结果路径换为可访问的高扇出提取结果。

```bash
python3 scripts/check_gui_workspace.py --geometry 1366x768 --exercise --out /tmp/ct7-desktop
python3 scripts/check_canvas_performance.py --result /path/to/fanout/clocktree.json --verify-trunk --out /tmp/ct7-benchmark.json
python3 scripts/check_workbench_gui.py --phase stress --result examples/device_models/clocktree.json --out /tmp/ct7-stress
```

在第一条命令中追加 `--capture` 可保存 X11 实际窗口截图。追加 `--extract-config /path/to/config.json` 可执行 GUI 实时提取。将已知正确的 `clocktree.json` 与测试配置放在同一目录，脚本会核对每个实例和每条连接的源、目标端口。
